這堂課要完成什麼？

學生已經會使用 BH1750FVI，本節課重點是理解 D1 mini 的網路能力，並把感測器資料送到雲端。

認識 D1 mini 網路功能

D1 mini 本身就有 Wi-Fi 功能，不需要另外接網路模組。只要使用 MicroPython 的 network 模組，就能連接無線網路。

讀取光照感測資料

利用 I2C 讀取 BH1750FVI 的亮度值，單位為 lux，並在序列埠中觀察即時資料。

上傳到雲端試算表

透過 Replit 橋接 Make Webhook，再把資料寫入 Google Sheets，完成簡單的物聯網資料蒐集流程。

第一步：D1 mini 為什麼可以連 Wi-Fi？

很多同學會以為開發板要另外接網路模組才能上網，但 D1 mini 已經把 Wi-Fi 功能整合在板子上。

D1 mini 的角色

在這個實作中，D1 mini 同時扮演兩個角色：第一，它透過 I2C 讀取 BH1750FVI 的光照資料；第二，它連上 Wi-Fi， 讓資料可以被送到雲端服務。

  • 讀取感測器
  • 連接 Wi-Fi
  • 發送 HTTP Request
  • 上傳雲端

本程式用到的腳位

BH1750FVI 使用 I2C 溝通，因此程式中設定 SCL 與 SDA 腳位。

程式一：連上 Wi-Fi 並讀取亮度

請先把 Wi-Fi 名稱與密碼改成自己的網路，再將程式貼到 MicroPython 環境中執行。

main.py｜讀取亮度測試 
import network, urequests, utime, bh1750fvi
from machine import Pin, I2C

# 建立 I2C 連線：SCL 使用 GPIO5，SDA 使用 GPIO4
i2c = I2C(scl=Pin(5), sda=Pin(4))

# 請改成自己的 Wi-Fi 名稱與密碼
ssid = "請填入你的 WiFi 名稱"
pw = "請填入你的 WiFi 密碼"

print("連接 WiFi...")
wifi = network.WLAN(network.STA_IF)
wifi.active(True)
wifi.connect(ssid, pw)

while not wifi.isconnected():
    pass
print("已連上")

while True:
    light_level = bh1750fvi.sample(i2c, mode=0x23)
    print("亮度: " + str(light_level) + " lux")
    utime.sleep(3)
程式碼 說明
network.WLAN(network.STA_IF) 讓 D1 mini 進入 Wi-Fi 用戶端模式，像手機或筆電一樣去連接分享器。
wifi.active(True) 啟用 Wi-Fi 功能。
wifi.connect(ssid, pw) 使用指定的 Wi-Fi 名稱與密碼進行連線。
while not wifi.isconnected() 在尚未連上 Wi-Fi 前持續等待。
bh1750fvi.sample(i2c, mode=0x23) 透過 I2C 讀取 BH1750FVI 光照感測器的亮度值。

程式二：讀取亮度並呼叫 Make

這段程式會每 5 秒讀取一次亮度，並把亮度值透過 Replit 轉送給 Make Webhook。

main.py｜亮度資料上傳 
import network, urequests, utime, bh1750fvi
from machine import Pin, I2C

i2c = I2C(scl=Pin(5), sda=Pin(4))

# 請改成自己的 Wi-Fi 名稱與密碼
ssid = "請填入你的 WiFi 名稱"
pw = "請填入你的 WiFi 密碼"

print("連接 WiFi...")
wifi = network.WLAN(network.STA_IF)
wifi.active(True)
wifi.connect(ssid, pw)

while not wifi.isconnected():
    pass
print("已連上")

# 請貼上你在 Make 取得的 Webhook URL
url = "請貼上你的 Make Webhook URL"

# 請貼上你在 Replit Preview 複製到的網址
replit_url = "請貼上你的 Replit URL"

while True:
    light_level = bh1750fvi.sample(i2c, mode=0x23)

    response = urequests.get(
        replit_url + "?url=" + url + "?value=" + str(light_level)
    )

    if response.status_code == 200:
        print("MAKE 呼叫成功: 傳送亮度 " + str(light_level) + " lux")
    else:
        print("MAKE 呼叫失敗")

    response.close()
    utime.sleep(5)
為什麼要加 response.close()？ D1 mini 的記憶體較小，每次發送請求後關閉 response，可以降低長時間執行時記憶體不足的機率。

作業挑戰：只在開燈或熄燈狀態改變時傳送資料

前面的程式每 5 秒都會傳送資料。作業目標是加入狀態判斷，讓程式只在狀態改變時傳送「開燈」或「熄燈」。

作業需求

  • 讀取 BH1750FVI 的亮度值。
  • 當亮度小於或等於 0，且上一個狀態是開燈，才傳送「熄燈」。
  • 當亮度大於 0，且上一個狀態是熄燈，才傳送「開燈」。
  • 不要每 5 秒重複傳送同一個狀態。

狀態變數 n 的概念

可以把 n 想成目前狀態的紀錄：n = 0 代表目前記錄為熄燈， n = 1 代表目前記錄為開燈。只有當亮度狀態和記錄不同時，才需要傳送資料。

提醒： 「開燈」判斷建議加入 light_level > 0。 如果只寫 elif n == 0，即使環境仍然是暗的，下一輪也可能再次送出「開燈」。
展開參考解答程式碼
main.py｜作業參考解答 
import network, urequests, utime, bh1750fvi
from machine import Pin, I2C

i2c = I2C(scl=Pin(5), sda=Pin(4))

# 請改成自己的 Wi-Fi 名稱與密碼
ssid = "請填入你的 WiFi 名稱"
pw = "請填入你的 WiFi 密碼"

print("連接 WiFi...")
wifi = network.WLAN(network.STA_IF)
wifi.active(True)
wifi.connect(ssid, pw)

while not wifi.isconnected():
    pass
print("已連上")

# 請貼上你在 Make 取得的 Webhook URL
url = "請貼上你的 Make Webhook URL"

# 請貼上你在 Replit Preview 複製到的網址
replit_url = "請貼上你的 Replit URL"

# n = 0：目前紀錄為熄燈
# n = 1：目前紀錄為開燈
n = 0

while True:
    light_level = bh1750fvi.sample(i2c, mode=0x23)

    # 從開燈變成熄燈
    if light_level <= 0 and n == 1:
        response = urequests.get(
            replit_url + "?url=" + url + "?value=" + str(light_level) + "&text=" + "熄燈"
        )
        n = 0

        if response.status_code == 200:
            print("MAKE 呼叫成功: 傳送亮度 " + str(light_level) + " lux，狀態：熄燈")
        else:
            print("MAKE 呼叫失敗")

        response.close()

    # 從熄燈變成開燈
    elif light_level > 0 and n == 0:
        response = urequests.get(
            replit_url + "?url=" + url + "?value=" + str(light_level) + "&text=" + "開燈"
        )
        n = 1

        if response.status_code == 200:
            print("MAKE 呼叫成功: 傳送亮度 " + str(light_level) + " lux，狀態：開燈")
        else:
            print("MAKE 呼叫失敗")

        response.close()

    utime.sleep(5)

常見問題檢查

如果程式沒有成功連線或試算表沒有收到資料，可以依序檢查以下項目。

Wi-Fi 連不上

  • 確認 SSID 與密碼是否正確。
  • 建議使用 2.4 GHz Wi-Fi 或手機熱點。
  • 如果使用 iPhone 熱點，可嘗試開啟「最大化相容性」。
  • 確認 D1 mini 已經成功燒錄 MicroPython，且程式有重新執行。

Make 沒有收到資料

  • 確認 Make Scenario 已經開啟自動執行。
  • 確認 Webhook URL 是否貼到 url。
  • 確認 Replit Preview URL 是否貼到 replit_url。
  • 先用瀏覽器測試 Webhook 是否能出現 Accepted。

課堂成果檢核

  • 序列埠能看到「已連上」。
  • 序列埠能看到亮度數值，例如 亮度: 603 lux。
  • 執行上傳程式後，序列埠能看到 MAKE 呼叫成功。
  • Google 試算表會新增亮度資料列。
  • 作業完成後，試算表能記錄「開燈」與「熄燈」狀態。
